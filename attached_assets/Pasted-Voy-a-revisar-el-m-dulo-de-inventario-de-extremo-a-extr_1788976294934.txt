Problemas encontrados
1. Anular una venta desde el listado no devuelve el stock
Este es el problema más importante.

La venta se puede marcar como anulado desde:

/casadets/ventas/{venta}/estado

Ese flujo está en VentaController::updateEstado() y solo:

Cambia el estado de la venta.
Anula los movimientos financieros relacionados.
No crea ningún movimiento de entrada de inventario.

Además, después de marcarla como anulado, el flujo correcto de devoluciones ya no permite anularla nuevamente para devolver el stock.

Resultado: una venta anulada desde el listado puede dejar el inventario reducido permanentemente.

La anulación desde la sección de devoluciones sí devuelve correctamente el stock, pero existen dos caminos diferentes para anular.

Prioridad: alta.

2. Los productos pueden mezclarse entre CASADETS y ZENDY
Aunque el producto tiene campo empresa, las operaciones automáticas buscan productos solamente por nombre:

Producto::firstOrCreate(['nombre' => $nombre])

Esto ocurre en:

Ventas manuales.
Importación de ventas.
Compras.
Consecuencias:

Un producto con el mismo nombre en CASADETS y ZENDY se comparte.
Una compra o venta de ZENDY puede usar un producto creado como CASADETS.
El inventario queda mezclado entre empresas.
El campo de filtro por empresa no corrige la mezcla original.
También la validación manual de productos considera único el nombre globalmente, no por empresa.

Prioridad: alta si ambas empresas manejan inventario separado.

3. El ajuste absoluto usa el stock cacheado
En ProductoController::storeAjuste(), el ajuste absoluto calcula la diferencia usando:

$producto->stock_actual

Pero la fuente de verdad declarada es el kardex.

Si stock_actual está desactualizado, el ajuste puede quedar incorrecto. Debería calcularse desde:

$producto->stockDesdeKardex()

y luego recalcular el cache.

Prioridad: media.

4. El inventario permite vender con stock negativo
No encontré validación que impida vender más unidades que las disponibles.

El sistema permite:

Stock actual: 2
Venta: 5
Resultado: stock -3

La interfaz solamente marca el producto como stock bajo cuando el valor es menor o igual a cero.

Esto puede ser correcto si se permiten ventas contra inventario futuro, pero actualmente no existe una configuración o advertencia fuerte que diferencie ambos comportamientos.

Prioridad: decisión de negocio.

5. El kardex no conserva movimientos históricos al eliminar
Al eliminar una venta o compra, se borran físicamente sus movimientos de stock_movimientos.

Eso mantiene el stock numéricamente correcto, pero el kardex pierde el registro histórico de la operación.

Para un inventario auditable sería mejor conservar el movimiento original y crear un movimiento compensatorio de entrada o salida.

Prioridad: media, dependiendo del nivel de auditoría requerido.

6. Los permisos específicos de productos no están aplicados en las rutas
Existe un catálogo de permisos para:

El rol Cajero tiene acceso al módulo de productos, pero no tiene esos permisos específicos en la configuración predeterminada. Sin embargo, por las rutas actuales podría acceder a esas acciones.

Además, los botones de crear, editar y ajustar aparecen directamente en las vistas sin verificar permisos individuales.

Prioridad: alta en seguridad operativa.

El kardex no tiene caja_id.

Por tanto, todas las cajas comparten el mismo inventario de cada producto. La caja activa no afecta al stock.

Esto está bien si el inventario es centralizado, pero no si cada caja representa un almacén físico independiente.
